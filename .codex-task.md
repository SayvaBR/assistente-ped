## Lane A — Onboarding Entry V2

The current first screen after Splash is rejected as composition. Do not polish it in place.

Rebuild in `src/v2/` following `SCREEN_SPEC_ONBOARDING_ENTRY_V2.md`.

Target language: Friendly Professional + Candy UI + Tactile + Educational + Motion-led.

Requirements:

- compact top area;
- tactile mini teacher workspace, not isolated generic icon;
- headline around 2 lines at 390px;
- short subcopy;
- consequence proof integrated into composition;
- primary CTA visible in first viewport;
- no mascot/owl;
- no SaaS dashboard/Material/template look.

Fast loop:

`edit -> HMR -> 390 render -> screenshot -> visual_director critique -> fix highest-impact difference -> repeat`

During micro-iterations use only:

`pnpm run check:fast`

Do not run Android or full E2E for CSS/composition iterations.

## Candidate gate

When the first 390px version looks convincing:

1. ask `visual_director` for a second critique;
2. apply the single highest-impact remaining correction;
3. start `qa_reviewer` for responsive/accessibility/regression review;
4. validate 360/430;
5. run `pnpm run check:candidate`;
6. run only the E2E/test directly related to onboarding if available.

## Stop condition

As soon as there is a strong candidate, stop expansion and report:

`READY FOR DESIGN REVIEW — ONBOARDING ENTRY V2`

Include:

- screenshot 390px;
- branch + commit/worktree;
- result of `check:fast` / `check:candidate`;
- visual_director verdict;
- qa_reviewer findings;
- 3 remaining refinements, if any;
- UI Lab status.

Do not merge automatically. Do not advance to unrelated screens before review.
